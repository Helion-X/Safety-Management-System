HELION-X OPERATING MANUAL

This manual covers all functions visible in the supplied Helion-X HOME, SMS, CMS, OMM Appendices and Safety/Security Report files. It is designed as an operational user guide: what each module is for, how to enter and review data, how records link together, and what must be checked before saving, exporting or closing.

Το εγχειρίδιο καλύπτει όλες τις λειτουργίες που εμφανίζονται στα αρχεία Helion-X HOME, SMS, CMS, OMM Appendices και Safety/Security Report. Είναι επιχειρησιακός οδηγός: σκοπός κάθε module, data entry/review, συνδέσεις μεταξύ records και έλεγχοι πριν από save, export ή close.

1. Helion-X overview

Helion-X is the management portal that brings together the Safety Management System (SMS), Compliance Monitoring System (CMS), OMM Appendices and the Safety/Security reporting form. The home page is the normal starting point.

From the home page

  1. Select SMS for risks, occurrences, change management, ERP, safety indicators and safety assurance.
  2. Select CMS for audit planning, findings, corrective actions, compliance matrices, regulatory watch, SRB and annual reporting.
  3. Select OMM for the controlled OMM appendices, management lists, aircraft list and safety-promotion/training records.
  4. Select Safety Report when a user needs to submit a safety, security or Part-IS related report.
  5. Select User Guide / Οδηγός Χρήστη to open this manual.
Recommended practice: use the HOME/SMS/CMS/OMM navigation bar rather than the browser Back button when moving between Helion-X management modules.

1. Επισκόπηση Helion-X

Το Helion-X είναι η πύλη διαχείρισης που συγκεντρώνει το Σύστημα Διαχείρισης Ασφάλειας (SMS), το Σύστημα Παρακολούθησης Συμμόρφωσης (CMS), τα Παραρτήματα OMM και τη φόρμα αναφοράς Safety/Security. Η αρχική σελίδα είναι το κανονικό σημείο εκκίνησης.

Από την αρχική σελίδα

  1. Επιλέξτε SMS για κινδύνους, συμβάντα, διαχείριση αλλαγών, ERP, δείκτες ασφάλειας και safety assurance.
  2. Επιλέξτε CMS για προγραμματισμό ελέγχων, ευρήματα, διορθωτικές ενέργειες, πίνακες συμμόρφωσης, κανονιστική παρακολούθηση, SRB και ετήσια αναφορά.
  3. Επιλέξτε OMM για τα ελεγχόμενα παραρτήματα OMM, τις λίστες διοίκησης, τον στόλο και τα αρχεία safety promotion/εκπαίδευσης.
  4. Επιλέξτε Safety Report όταν πρέπει να υποβληθεί αναφορά safety, security ή Part-IS.
  5. Επιλέξτε User Guide / Οδηγός Χρήστη για αυτό το εγχειρίδιο.
Συνιστώμενη πρακτική: χρησιμοποιείτε τη γραμμή HOME/SMS/CMS/OMM αντί για το κουμπί Back του browser όταν μετακινείστε μεταξύ των κύριων modules.

2. Access, roles and read-only mode

Helion-X distinguishes between users who may modify data and users who may only view data.

RoleTypical rights
AdminRead/write access to management modules; administrative restore functions may also be available.
EditorRead/write access to the operational management modules.
AuthorityViewing access only. Editing controls are intentionally disabled.
Reader / GuestViewing access only; the portal may restrict the modules shown to the user.

Signing in

  1. On HOME or a module, select the login control when displayed.
  2. Enter the Helion-X account email and password.
  3. Check the role badge after authentication. If the badge shows READ ONLY unexpectedly, do not attempt to work around the restriction; ask the system administrator to verify the declared role/email.
  4. When finished, use Sign out / Log out on a shared computer.
Important: a disabled field or Save/Add/Delete button in read-only mode is a permission control, not a malfunction.

Το Helion-X διαχωρίζει τους χρήστες που μπορούν να τροποποιούν δεδομένα από εκείνους που έχουν μόνο δικαίωμα προβολής.

3. Saving, synchronization, exports and backups

Different Helion-X modules use a combination of local browser storage, cloud synchronization and explicit export files. Treat an export as a controlled backup, not as a substitute for completing the normal Save workflow.

Safe working sequence

  1. Make the change in the relevant module.
  2. Use the module-specific Save button when one exists.
  3. Allow the cloud/status indicator to return to a normal/connected state before closing the browser.
  4. For significant changes, export JSON/CSV/PDF as appropriate to the record type.
  5. Before a restore/import, create a fresh export of the current state.

What the export formats are for

  • JSON: full or module backup designed for re-import/restore.
  • CSV: tabular analysis, registers and traceability in Excel-compatible form.
  • PDF / Print: controlled snapshot for review, signature, filing or authority evidence.
  • HTML: used in the OMM module to save a self-contained updated working file.
Restore/import is potentially destructive. Confirm that the selected file belongs to the correct Helion-X environment and that a current backup exists before replacing data.

3. Αποθήκευση, συγχρονισμός, εξαγωγές και αντίγραφα ασφαλείας

Τα modules του Helion-X χρησιμοποιούν συνδυασμό τοπικής αποθήκευσης browser, cloud synchronization και ρητών αρχείων export. Το export είναι ελεγχόμενο backup και όχι υποκατάστατο της κανονικής διαδικασίας Save.

Ασφαλής σειρά εργασίας

  1. Κάντε την αλλαγή στο σωστό module.
  2. Χρησιμοποιήστε το ειδικό κουμπί Save όταν υπάρχει.
  3. Περιμένετε το cloud/status indicator να επιστρέψει σε κανονική/connected κατάσταση πριν κλείσετε τον browser.
  4. Για σημαντικές αλλαγές εξάγετε JSON/CSV/PDF ανάλογα με το αρχείο.
  5. Πριν από restore/import δημιουργήστε νέο export της τρέχουσας κατάστασης.

Χρήση των μορφών export

  • JSON: πλήρες ή module backup για re-import/restore.
  • CSV: πίνακες, μητρώα και ανάλυση συμβατή με Excel.
  • PDF / Print: ελεγχόμενο στιγμιότυπο για review, υπογραφές, αρχειοθέτηση ή evidence προς αρχή.
  • HTML: χρησιμοποιείται στο OMM για αποθήκευση ενημερωμένου αυτοτελούς αρχείου.
Το restore/import μπορεί να αντικαταστήσει δεδομένα. Βεβαιωθείτε ότι το αρχείο ανήκει στο σωστό περιβάλλον Helion-X και ότι υπάρχει πρόσφατο backup.

4. Recommended cross-module workflow

Use the modules as one management system rather than isolated registers.

  1. Report / detect: receive a mobile Safety/Security report, an audit finding, a CAMO signal or another safety input.
  2. Classify: in the SMS Occurrence Log, assign the occurrence category, SMS family and event/risk linkage.
  3. Assess: create or update the corresponding Risk Register entry when risk exposure changes.
  4. Act: use corrective actions in the occurrence, a CMS CAP for compliance findings, or a Management of Change study for an organisational/operational/technical change.
  5. Verify effectiveness: record control status, due date, evidence and effectiveness review rather than closing an action solely because it was implemented.
  6. Review: use SPI/KPI dashboards, SRB, Safety Assurance and annual CMS reporting to confirm trends and management decisions.
Traceability rule: whenever the interface offers a linked risk ID, change-study reference, finding reference or document reference, use it. These links are what turn separate entries into an auditable management chain.

4. Συνιστώμενη ροή μεταξύ modules

Χρησιμοποιείτε τα modules ως ένα ενιαίο management system και όχι ως ανεξάρτητα μητρώα.

  1. Report / detect: λήψη mobile Safety/Security report, audit finding, CAMO signal ή άλλου safety input.
  2. Classify: στο SMS Occurrence Log αντιστοιχίστε occurrence category, SMS family και σύνδεση event/risk.
  3. Assess: δημιουργήστε ή ενημερώστε το αντίστοιχο Risk Register entry όταν αλλάζει η έκθεση σε κίνδυνο.
  4. Act: χρησιμοποιήστε corrective actions στο occurrence, CMS CAP για compliance findings ή Management of Change για οργανωτική/επιχειρησιακή/τεχνική αλλαγή.
  5. Verify effectiveness: καταγράψτε control status, due date, evidence και effectiveness review· μην κλείνετε ενέργεια μόνο επειδή εφαρμόστηκε.
  6. Review: χρησιμοποιήστε SPI/KPI dashboards, SRB, Safety Assurance και annual CMS reporting για τάσεις και διοικητικές αποφάσεις.
Κανόνας ιχνηλασιμότητας: όπου υπάρχει linked risk ID, change-study reference, finding reference ή document reference, συμπληρώστε το. Αυτές οι συνδέσεις δημιουργούν auditable αλυσίδα διαχείρισης.

5. Safety / Security Report

The reporting form is intended for rapid submission of flight-safety occurrences, security/unlawful-interference events and information-security events.

Step-by-step

  1. Choose SAFETY or SECURITY. The form reveals only the fields relevant to the selected branch.
  2. Decide whether the report is Anonymous. Anonymous reporting removes identity data; for security reports, remember that anonymity can limit follow-up.
  3. Select the entity concerned (Operations, CAMO, Part 145 or Other).
  4. Complete the event type and the aircraft/operation fields that become applicable.
  5. Enter the Date, local time and Location of event.
  6. Describe what happened in factual chronological order. Separate observations from assumptions.
  7. Record immediate actions already taken, external notifications already made and any useful comments/suggestions.
  8. Attach photos/files when they materially help the investigation and do not expose unnecessary sensitive information.
  9. Select SUBMIT REPORT. Do not leave the page until the success screen and report reference are displayed.

If submission cannot reach the backend

The form includes a local pending-report mechanism. If connectivity is unreliable, preserve the device/browser state and retry when connection is restored rather than creating multiple duplicate reports.

Live emergency or ongoing security threat: follow the emergency/security call process first. The electronic report is not a substitute for immediate operational response.

5. Αναφορά Safety / Security

Η φόρμα reporting χρησιμοποιείται για γρήγορη υποβολή flight-safety occurrences, security/unlawful-interference events και information-security events.

Βήμα προς βήμα

  1. Επιλέξτε SAFETY ή SECURITY. Η φόρμα εμφανίζει μόνο τα σχετικά πεδία.
  2. Αποφασίστε αν η αναφορά θα είναι Anonymous. Η ανώνυμη αναφορά αφαιρεί στοιχεία ταυτότητας· στα security reports μπορεί να περιορίσει το follow-up.
  3. Επιλέξτε concerned entity (Operations, CAMO, Part 145 ή Other).
  4. Συμπληρώστε τον τύπο συμβάντος και τα aircraft/operation fields που εφαρμόζονται.
  5. Καταχωρίστε Date, local time και Location of event.
  6. Περιγράψτε τι συνέβη με πραγματική χρονολογική σειρά. Διαχωρίστε παρατηρήσεις από υποθέσεις.
  7. Καταγράψτε immediate actions, εξωτερικές notifications και χρήσιμα comments/suggestions.
  8. Επισυνάψτε photos/files μόνο όταν βοηθούν ουσιαστικά την έρευνα και χωρίς περιττά ευαίσθητα δεδομένα.
  9. Επιλέξτε SUBMIT REPORT. Μην φύγετε από τη σελίδα πριν εμφανιστεί success screen και report reference.

Αν δεν υπάρχει σύνδεση με το backend

Η φόρμα διαθέτει local pending-report mechanism. Σε ασταθή σύνδεση διατηρήστε το ίδιο browser/device state και επαναλάβετε όταν αποκατασταθεί η σύνδεση, αντί να δημιουργείτε διπλές αναφορές.

Ενεργή κατάσταση έκτακτης ανάγκης ή security threat: ακολουθήστε πρώτα την emergency/security διαδικασία. Η ηλεκτρονική αναφορά δεν αντικαθιστά την άμεση επιχειρησιακή αντίδραση.

6.2 APP08-OMM — Risk Register

The Risk Register is the core record of identified safety risk scenarios and their controls.

Finding an existing risk

  1. Use the free-text search first.
  2. Use Level 1 occurrence category and Level 2 SMS family filters to narrow the list.
  3. Open advanced filters only when needed. Active filters are shown so that you do not review a partially filtered register unknowingly.
  4. Use Compact when you need more rows on screen; this changes presentation, not data.

Creating or editing a risk

  1. Select + NEW ENTRY (or edit an existing line).
  2. Enter the unique Risk ID, Legacy Domain, Level 1 occurrence category and Level 2 SMS family.
  3. Write one clear Undesirable Event. Put causes/exposure in Dangers / Hazards and outcomes in Consequences.
  4. Describe Prevention, Mitigation and Recovery measures separately when applicable.
  5. Assign Initial Risk before credited controls and Residual Risk after the stated controls.
  6. Complete control governance: Control Status, Last Control Date, Control Comment, Risk Owner and Effectiveness Due Date.
  7. Where used, define the Safety Performance Indicator, Target/Trigger, Effectiveness Verification Method and Formal Acceptance Basis/Conditions.
  8. Link a Management of Change study when the risk originates from or is materially affected by a change.
  9. Use PREVIEW to inspect the record and SAVE TO DATABASE to commit it.

Exports

PDF — Barrier Sheets creates barrier-oriented printable records; JSON is suited to backup; CSV is suited to register analysis.

Do not use a single row for several unrelated undesirable events. If the event, consequences or control set differ materially, create separate risk scenarios so that residual risk and effectiveness can be verified independently.

6.2 APP08-OMM — Μητρώο Κινδύνων

Το Risk Register είναι το βασικό αρχείο των αναγνωρισμένων safety risk scenarios και των controls τους.

Εύρεση υπάρχοντος risk

  1. Χρησιμοποιήστε πρώτα το free-text search.
  2. Χρησιμοποιήστε Level 1 occurrence category και Level 2 SMS family για περιορισμό.
  3. Ανοίξτε advanced filters μόνο όταν χρειάζεται. Τα ενεργά filters εμφανίζονται ώστε να μην εξετάζετε κατά λάθος μερικώς φιλτραρισμένο register.
  4. Χρησιμοποιήστε Compact για περισσότερες γραμμές στην οθόνη· αλλάζει μόνο την εμφάνιση.

Δημιουργία ή επεξεργασία risk

  1. Επιλέξτε + NEW ENTRY ή edit σε υπάρχουσα γραμμή.
  2. Καταχωρίστε μοναδικό Risk ID, Legacy Domain, Level 1 occurrence category και Level 2 SMS family.
  3. Γράψτε ένα σαφές Undesirable Event. Βάλτε αιτίες/έκθεση στα Dangers / Hazards και αποτελέσματα στα Consequences.
  4. Διαχωρίστε Prevention, Mitigation και Recovery measures.
  5. Ορίστε Initial Risk πριν από credited controls και Residual Risk μετά τα controls.
  6. Συμπληρώστε Control Status, Last Control Date, Control Comment, Risk Owner και Effectiveness Due Date.
  7. Όπου εφαρμόζεται ορίστε Safety Performance Indicator, Target/Trigger, Effectiveness Verification Method και Formal Acceptance Basis/Conditions.
  8. Συνδέστε Management of Change study όταν ο risk προέρχεται από ή επηρεάζεται ουσιαστικά από αλλαγή.
  9. Χρησιμοποιήστε PREVIEW και μετά SAVE TO DATABASE.

Exports

Το PDF — Barrier Sheets δημιουργεί εκτυπώσιμα barrier records, το JSON είναι για backup και το CSV για ανάλυση register.

Μην βάζετε σε μία γραμμή πολλά άσχετα undesirable events. Αν event, consequences ή controls διαφέρουν ουσιαστικά, δημιουργήστε ξεχωριστά risk scenarios.

6.3 APP09-OMM — Management of Change

Use Management of Change (MoC) when a proposed or implemented change can affect safety, compliance, responsibilities, resources, procedures, technology or operations.

Create a study

  1. Select + New Change Study or NEW STUDY.
  2. Enter Title, Internal Reference and Safety Assessment Type.
  3. Indicate whether authority approval/authorisation is required before implementation.
  4. Set Workflow Status and maintain Version History. Use the version note when a revision changes the assessment.
  5. Describe the change, decision origin, duration, start/end dates and documentation/archiving impact.
  6. List applicable regulations and the assessor(s).
  7. If the change is triggered by an occurrence or CMS finding, use the root-cause/reference fields and lookup tools so the link is traceable.
  8. Identify change-related risk events. Import an existing Risk Register scenario where appropriate instead of rewriting a parallel, inconsistent risk.
  9. Complete cybersecurity/Part-IS fields when the change introduces information-security exposure.
  10. Add implementation actions with owner and follow-up status.
  11. Complete ACM/assessor acknowledgements, nominated-person involvement, effectiveness follow-up, conclusions and final approval.
  12. Use PREVIEW before SAVE CHANGE STUDY.
Closure criterion: a change study should not be treated as complete merely because the change has gone live. Record implementation evidence and confirm that the risk-reduction measures are effective.

6.3 APP09-OMM — Διαχείριση Αλλαγών

Χρησιμοποιήστε Management of Change (MoC) όταν μια προτεινόμενη ή υλοποιημένη αλλαγή μπορεί να επηρεάσει safety, compliance, responsibilities, resources, procedures, technology ή operations.

Δημιουργία study

  1. Επιλέξτε + New Change Study ή NEW STUDY.
  2. Συμπληρώστε Title, Internal Reference και Safety Assessment Type.
  3. Δηλώστε αν απαιτείται authority approval/authorisation πριν από implementation.
  4. Ορίστε Workflow Status και διατηρήστε Version History. Χρησιμοποιήστε version note όταν η revision αλλάζει την assessment.
  5. Περιγράψτε change, decision origin, duration, start/end dates και documentation/archiving impact.
  6. Καταγράψτε applicable regulations και assessors.
  7. Αν η αλλαγή προέρχεται από occurrence ή CMS finding, χρησιμοποιήστε root-cause/reference και lookup ώστε η σύνδεση να είναι traceable.
  8. Αναγνωρίστε change-related risk events. Κάντε import existing Risk Register scenario όπου είναι σωστό.
  9. Συμπληρώστε cybersecurity/Part-IS fields όταν υπάρχει information-security exposure.
  10. Προσθέστε implementation actions με owner και follow-up status.
  11. Συμπληρώστε ACM/assessor acknowledgements, nominated-person involvement, effectiveness follow-up, conclusions και final approval.
  12. Χρησιμοποιήστε PREVIEW πριν από SAVE CHANGE STUDY.
Κριτήριο closure: ένα MoC δεν θεωρείται ολοκληρωμένο μόνο επειδή η αλλαγή τέθηκε σε λειτουργία. Καταγράψτε evidence και επιβεβαιώστε effectiveness των risk-reduction measures.

6.4 APP10-OMM — Emergency Response Plan

The ERP view is both a reference and a crisis-working tool. It contains contacts, checklists, a crisis log, roles and general/return information.

  1. Use CONTACTS to access the call chain and emergency contacts.
  2. Use CHECKLIST during activation so required information and decisions are not missed.
  3. Use CRISIS LOG to add time-stamped entries. Record facts, calls, decisions, instructions and handovers.
  4. Use ROLES to allocate crisis-management responsibilities.
  5. Use GENERAL and RETURN for supporting procedures and return-to-normal activities.
  6. Use Print ERP to create an offline/filing copy when required.
Reset is a destructive control. Do not use it during a live activation unless you are deliberately clearing test/training data and have preserved the required record.

6.4 APP10-OMM — Σχέδιο Αντιμετώπισης Έκτακτης Ανάγκης

Το ERP είναι ταυτόχρονα reference και εργαλείο εργασίας σε κρίση. Περιλαμβάνει contacts, checklists, crisis log, roles και general/return information.

  1. Χρησιμοποιήστε CONTACTS για call chain και emergency contacts.
  2. Χρησιμοποιήστε CHECKLIST κατά την activation για να μη χαθούν απαιτούμενες πληροφορίες/αποφάσεις.

9. Closing a Helion-X module

Where a module offers a Close button or Save/Export overlay, use it rather than simply closing the browser tab during editing.

  1. Finish the current entry and use its Save control.
  2. Check the module status/cloud indicator.
  3. Create the required export if the change is significant or forms a controlled record.
  4. Use Close and confirm the prompt only after the save/export has completed.
  5. If the browser crashes, reopen the same module and verify the record before continuing work.

9. Κλείσιμο Helion-X module

Όπου το module διαθέτει Close ή Save/Export overlay, χρησιμοποιήστε το αντί να κλείνετε απλώς το browser tab κατά το editing.

  1. Ολοκληρώστε το current entry και Save.
  2. Ελέγξτε module status/cloud indicator.
  3. Δημιουργήστε required export για significant/controlled record.
  4. Χρησιμοποιήστε Close και επιβεβαιώστε prompt μόνο μετά την ολοκλήρωση save/export.
  5. Μετά από browser crash ξανανοίξτε το module και verify το record πριν συνεχίσετε.
